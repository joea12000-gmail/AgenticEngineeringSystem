Agentic Engineering System — Proof of Concept

This single-page artifact summarizes the POC, how it is wired, how to run it locally, and sample API calls to exercise the orchestration and URL shortener slices.

Purpose

Provide a runnable, small-surface POC demonstrating:

  • Minimal ASP.NET Core HTTP API surface for the URL shortener and governance workflows.
  • Entity model and persistence using EF Core with an in-memory SQLite connection (shared open connection lifetime).
  • A simple WorkflowEngine prototype that evaluates task dependencies and supports human approvals.

Architecture (high level)

Solution projects:

  • src/AgenticEngineeringSystem.Api — Minimal API host and endpoints.
  • src/AgenticEngineeringSystem.Core — Domain models (ShortUrl, UrlVisit, EngineeringWorkflow, EngineeringTask), contracts and policy types.
  • src/AgenticEngineeringSystem.Infrastructure — EF Core DbContext (AgenticEngineeringDbContext), in-memory SQLite wiring, WorkflowEngine, and services.
  • tests/AgenticEngineeringSystem.Tests — MSTest tests exercising the in-memory DB and orchestrator.

Data model snapshot

  • ShortUrl — original URL, ShortCode, visits relation.
  • UrlVisit — visit metadata (IP, UA, referrer, timestamp).
  • EngineeringWorkflow — contains a collection of EngineeringTask.
  • EngineeringTask — has Agent, Status, and possibly dependency edges (EngineeringTaskDependency).
  • AuditEvent — lightweight audit trail entries for approvals and actions.

EF Core + In-memory SQLite

The POC uses a single open SqliteConnection with Data Source=AgenticEngineeringSystem;Mode=Memory;Cache=Shared opened at startup and registered as a singleton. All DbContext instances use that connection via UseSqlite(connection). This keeps data available across separate DbContext instances in the same process for the POC lifetime. Tests use DataSource=:memory: with an open connection per test.

How to run locally

  powershell
  dotnet build AgenticEngineeringSystem.slnx
  dotnet test AgenticEngineeringSystem.slnx
  dotnet run --project .\src\AgenticEngineeringSystem.Api\AgenticEngineeringSystem.Api.csproj

The API binds to the default Kestrel address. Swagger UI is available at /swagger in Development.

Useful API endpoints (POC)

  • GET /health
  • POST /api/urls — create short URL; body: { "originalUrl": "https://example.com/article/1", "customCode": "example-1" }
  • GET /{shortCode} — redirect to original URL (records a visit)
  • GET /api/workflows — list workflows
  • POST /api/workflows/{workflowId}/tasks/{taskId}/approve — approve a task requiring human approval
  • POST /api/workflows/{workflowId}/tasks/{taskId}/reject — reject a task

Sample sequence (approval gate)

  1. Create a workflow with two tasks: taskA (agent) and taskB (human reviewer) where taskB depends on taskA.
  2. Run the orchestrator (background service or manual invocation) — taskA will execute immediately; taskB will be marked Blocked waiting approval.
  3. POST to the approve endpoint for taskB — orchestrator will pick it up and execute.
